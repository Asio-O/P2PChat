# Agent Note: 门禁证据纪律 —— 缺了实测轮次与署名的数字不是证据

Status: implemented

## Problem

本仓库有一类失败，在代码里什么痕迹都不留下：门禁跑出绿的，而产品是坏的；某个数字从一份记录的是另一次运行的文档里被引用过来；一条警告计数从一条本身就记错的记录里被照抄下来。这些都不是缺陷——没有任何一次提交引入它们，没有任何测试能抓到它们，修好一个也不会让 `src/` 下改动一行。它们是流程性的失败，而且是代价最高的那一类，因为每一条都把一个未经证实的说法变成一个读起来像已证实的说法。

损害以一种特定的方式叠加。门禁值的含义是「这个值、来自这次运行、在这棵树上」。轮次与署名一旦被去掉，这个值就不再是证据，而变成传闻——而引用正是失效机制：一个没人重新推导过的值，就是一个没人会注意到它变陈旧的值。陈旧的值**看起来不陈旧**，它读起来与一个正确的值一模一样。而最容易被原样引用的文档，恰恰是摘要行与代码块，因为它们最好整段搬走。

这些教训原本寄居在仓库根目录的两份工作文档里，而两份现都已冻结进 `archived/`。归档记录永不再编辑，也永不作为现行权威，因此**只存在于那里的规则已经不再是规则**。本篇是这套纪律的活动归属；它记录规则，因此自身不含任何实测值。

## Decision

六条规则。每条都配它所防住的那一次具体事故——指不出事故的规则是偏好，不是门禁纪律。

## 1. The formal gate is a fixed command set, and an incremental build is never evidence

构建门禁是 `dotnet build P2PChat.slnx -t:Rebuild --no-incremental`，配套的测试运行**不加** `--no-build`。

这两个开关**两个都写**，且不是二选一。后来的读者若觉得其中一个冗余而删掉，被删掉的那个正是承载要求的那一个。

它们防住的事故：基于时间戳的增量判定可以认为一个含编译错误的文件「无需重编」，于是错误根本到不了编译器；而 `--no-build` 随后执行的是早先那次运行产出的二进制，它是通过的。**两者互相掩护**，而它们的组合与一次真通过无法区分——同样绿、同样退出码、同样没有任何诊断。本仓库曾有一个藏在测试项目里的编译错误活到强制重建才暴露，而增量运行在此期间一直报干净。

门禁的其余部分是 `dotnet test P2PChat.slnx`、`dotnet publish src/P2PChat.App/P2PChat.App.csproj -c Release` 与 `scripts/e2e-verify.ps1`。某次改动*需要*其中哪些属于另一个问题，归推送前那套 skill；本篇管的是值一旦写下之后它意味着什么。

## 2. A value reported by someone else finds problems; it never records results

门禁值是对一次运行的断言。把队员报的数抄进表格，等于把它归到记录者没跑过的那次运行上，而后来的读者分不出这两者——因为两种情况下那句话一模一样。

队员的运行是发现真问题最快的路径，也是制造假保证最省事的路径。这条规则不是不信任，而是：**记录者必须是跑的人**。门禁表的署名列写的是实际执行该命令的人；表作者自己没测过的值，是关于别人那棵树的证据。

## 3. A cell that cannot be attributed to a run stays empty

每一格都带一个实测值与测量者的名字。取不到时就留空，并写明待填。

它防住的事故：一张等着填的表承受着「看起来已经完成」的压力，而最容易够到手的值是更早那次记录里那个看起来合理的值。**一个背后没有轮次的值，比空白更糟。** 空白说的是「未实测」，会促使人重跑；填上的格说的是「已实测」，于是没人再看第二眼。空是门禁表的合法状态，而且必须**显式出现在表里**，不能靠「没写」来暗示。

## 4. One quantity, one home

权威表说了算。同一个量的其他每一处出现——摘要行、代码块、第二张表——都在同一次改动里一起改成与它一致。

它防住的事故：同一个值在几处被复述，而只有其中一处被改。只改权威表会留下一份读起来与正确值一模一样的副本，而最可能被原样引用的正是摘要行与代码块。**约定「权威表优先」是不够的；副本必须跟它一起改。**

可执行的形式：改完门禁表之后，把每个变过的值在全仓搜一遍，确认每一处出现都一致。本仓库曾让同一个值在同一份文档里以两种互不相符的形式并存，同时还有一个合计数不等于它所依据的分项之和——那类算术只要没人重加一遍分项就会一直活着。

## 5. A changed third-party AOT warning count is re-judged from the output, never inherited

这个计数是对一份工具输出所做的人工判断，这正是它能被照抄存活的原因。本仓库既有的记录里，某个第三方程序集被按产生两条诊断计入，实际只产生一条，而该错误在被发现之前就已经被引用传播过一次。**照抄计数会以全新的权威再传播一次这个错误**，因为晚写下的数字看起来像是当时核对过的。

后半句是一条禁令：这一格**永不**被简写成 0。它的值是「第三方代码路径本身不 trim / AOT 友好，而本产品不走那些路径」这一人工判断的结果。**没有任何工具认证过它**，把它改写成一个干净的 0，等于把一次判断换成一次不劳而获的通过。

## 6. An end-to-end gate's red runs are part of its result

只有最后的绿被记录下来，而这抹掉了故障在哪一层——那恰恰是最难恢复的一半。

本仓库端到端脚本里查出的两个根因**都在脚本侧，不在产品侧**。一条断言用较早阶段的节点身份去寻址较晚阶段的实例，而数据目录不同使两个身份确实不同；该断言此前一直通过，**仅仅因为它所走的那条代码路径对输入不做任何校验**，于是把寻址改对反而把通过变成了失败。另一条把参数以错误的顺序传给一条命令，本应作为一个字段的值被存成了两段拼接。两者都是靠读输出里决定性的那一行定位的，不是靠猜；而且都是「脚本每多一个阶段就会复现」的那类故障。

一个只报过绿的门禁，让后来的读者无法区分「被磨炼过的脚本」与「从未错过过的脚本」。

## Alternatives considered

**把门禁交给 CI，本地不再跑。** 否决：本仓库是单机、无 CI，且套件中有一部分依赖真实 DHT 引导与真实 TCP，因此 CI 上跑它与本地跑**不是同一次观察**。更深的代价是：没有这套本地纪律时，同样的问题会在更晚的地方被回答——那里上下文更少，而那个值也已经没有署名人可问了。

**门禁数字不进版本控制，改为运行时生成。** 否决：这会让「这是哪一次的值」变得不可校验——重新生成的数字无法与上周某份文档里的断言比对。丢掉的是对轮次与署名的归属，而归属正是这套纪律的全部载荷。

**只保留总通过数，不分项目。** 否决：分项与合计必须自洽，因为合计是对分项唯一廉价可得的交叉校验。此条防住的正是那类算术：一个不等于分项之和的合计数，出现在一份其全部目的就是「可被引用」的文档里。

## Consequences

- 跑门禁的代价是真实存在的——含端到端脚本的一次全量本地运行要数分钟——而这套纪律要求树在整个窗口内保持静止。在一棵移动着的树上取到的值，描述的是一棵已经不存在的树。
- **门禁值有保质期。** `src/` 或 `tests/` 下任何改动都会让上一次运行记录的所有值失效。本篇不带任何数字也是同一个理由：规则是耐久的，值是会陈旧的那部分。
- 这里没有任何自动化。没有任何规则能阻止一份陈旧副本被写下；规则 4 里「回头搜那个值」这一步是习惯而不是门禁，不做它的复核者不会收到任何信号说它被跳过了。
- 这些规则约束的是**记录数值的那个人**，所以它们写成义务而不是建议。一个署不出名字的门禁不是门禁。
