# 用证据驱动性能优化

把宽泛的"让它快一点"变成**可复现**的用户路径测量与**小而准**的修复。本 skill 只立原则骨架——具体每个仓库的 benchmarks/、profile 设计、Node lane / 浏览器 lane 的细节，由该仓库按本骨架细则化。

## 1. 先把"端点"与"基线"对齐

在动手前，让所有人对下列五件事有一致答案：

- **测哪一段用户可见动作**——精确到一次会话、一次页面跳转、一次历史回放。
- **工作负载区间**——典型与尾部分各一份；不要只用"测得最差"或"测得最好"代表用户真实工作。
- **资源约束**——CPU、内存、I/O、网络的基线；不算 model/网络的可达延迟，除非显式说明。
- **可接受的微小行为差异**——一次优化可能挪动一句 log、一个发包时序；先列出这类被允许的差。
- **停止规则**——典型与尾部都达到目标区间，再继续只是浪费；或者反过来，达不到就停。

把后端测量与浏览器测量分开——一段快历史遍历不能证明快传输 / 快 paint / 快滚动 / 快输入响应。

## 2. 列用户路径，而不是写代码

不要一开始就读 profiler。**先**广搜用户真实会走的所有路径：

- 冷启动 → 首次历史读 → 重开 → 可写恢复
- 多回合 + 工具密集 → 单条大消息 / 大结果 → 子会话 → 频繁切会话
- 首屏传输 + fold → 首可用 paint → 旧页加载 → 滚动 → 工具展开 → 非激活视图激活
- 实时流 + 重连：长活动会话 → 工具叠加 → 结算 → 取消 → teardown

委托独立 subagent 时按上述域分；每个 agent 要证据（生产调用点、出现频率），不允许凭印象。

## 3. 建合成基准——在改代码**之前**

任何"我做一项优化"的证据，必须落到**可重复测量**的合成基准上：

- **覆盖典型 + 尾部**而不是"用同一个数乘 100"
- **使用仓库生产调用路径**——别为了"测得到"复制一份"等价实现"
- **保持输入 / 验证 / 完成条件 / 可达输出在 before 与 after 完全一致**
- **报告原始样本 + 选定的聚合**——不报"挑出来赢的那次"
- **保留原始 = 失败位置反例**：让"通过"的断言在原始实现上**真的**失败

> 这是骨架；具体每个仓库用什么 runner、放在 `benchmarks/` 还是 `tests/perf/`、怎么连 CI lane，由该仓库自己定。下面第 4 节只立"测量方法"的护栏。

## 4. 测量方法护栏

- **报告所有样本** + 用来判定胜负的统计量；不要拿"CPU 倍数"乘自己仓库的 bytes / 次数 / 无量纲比。
- **内存测量**分清 retained（仍可达的对象）与 transient（瞬时峰值）；更快但 unbounded retained 不是自动的胜利。
- **冷/暖样本**：冷用全新 child + 私有临时根；显式重置要热的缓存——别让 fixture setup 不自觉地预热了"声称是冷"的样本。
- **浏览器响应性**需要真实浏览器 + 真实输入 + 真实 UI 更新；Node fold、伪 DOM、自定义心跳节拍都不能证明浏览器响应性。
- **不要** 为了让回归通过而放宽阈值；也不要降到已观察到噪声底之下。

## 5. 一次只改一个因果

一次跑只能改一个变量。重新跑**两件事**：聚焦场景 + 它的端到端父级。

每次改动必须有一个**反例控制**：让现有断言在原始实现或"故意加回的那点代价"上**真的**失败。"阈值宽容到回归也能过"不是保护——它只是把不确定性藏起来。

## 6. 护栏——保行为、保归属

测量是补充，不是替代。性能优化必须同时满足：

- 跑归属的单元 / e2e / 快照测试，证明未销出新行为
- 保留模型可见 ↔ 日志一致的边界
- 不静默砍历史、跳工具结果、关不变量、改生命周期
- 需要"可见差异"（如末尾输出微调）→ 显式陈述 + 用 snapshot / e2e 验证

实测有保留副作用（GPU 占用、长期内存增长）→ 注明；如果副作用超过收益，**拒绝**这次优化。

## 7. 拒绝的常见借口

- "看起来慢一点可能就是它" → **要测量**
- "改一点就行" → **要反例控制**
- "典型用户不会这么用" → **要列用户路径**
- "副作用一点点" → **要量化**

## 8. 交付：把结果落到 PR

按所属仓库的证据格式写：

- 列出工作负载的 before / after 绝对值与比值
- 写出**端点**与内存语义（retained vs transient）
- 标出行为证据（哪些测试、哪些快照）
- 标出反例控制（让断言在原始实现上失败的证据）
- 标出已跑的精确检查
- 标出排除项（model / 网络延迟等）

把"作者报告的历史数字"与"新鲜本地测量"与"CI 测量"分三栏写，不要混。

每次决定只覆盖协议同意的场景；其余的简短排序写下来，下次再说。
