# 审查一个 PR

**这份 skill 是指导，不是清单。** 先验证并 fetch PR 的 live base 与精确 head，再跑 `<your scope reporter> --base <verified-base-ref> --head <verified-head-ref>`，再读 diff 与足够多的上下文。`<your scope reporter>` 给出路径与脏层，但不替代语义审查。base 改了或合了一次之后重新跑。

优先级：**正确性 > 生命周期 > 安全 > 被破坏的必需行为 > 风格**。一篇带一个扎实 blocker 的短审查比一份**全是 nit**的清单更值钱。

## 权威来源

- 仓库根 [`AGENTS.md`](../../AGENTS.md) 与 [`modules/AGENTS.md`](../../modules/AGENTS.md)：仓库 / 模块层面的常驻规则。
- 仓库 [`docs/AGENTS.md`](../../docs/AGENTS.md)：文档放置与散文纪律。
- [`skills/prose-standard/`](../prose-standard/SKILL.md)：注释 / 文档 / prompt / 可见字符串的覆盖与编辑判断。
- [`skills/test-reliability/`](../test-reliability/SKILL.md)：拥有资源、异步或 flaky 的测试 / fixture 的隔离与回归证明规则。
- 仓库测试策略文件：测试层级与门要求。
- [`notes/README.md`](../../notes/README.md) 与 [`notes/AGENTS.md`](../../notes/AGENTS.md)：设计理由。"与 ADR 不同意"是设计讨论，不是自动否决。

## 必查项（blocking）

1. **新增散文要语义审查**。用 [`skills/prose-standard/`](../prose-standard/SKILL.md) 严格审查每条新增或改动的 Markdown 段落、JSDoc、注释、prompt、description、诊断、可见字符串。核对覆盖、准确性、放置、编辑质量是否能扛得起"放在那里给维护者读"；自动检查**不能**建立这些属性。
2. **文档与代码同步**。配置、默认值、错误、网络字段、事件、公开行为的改动在**同一个 diff** 里更新模块 README 与 JSDoc 契约。注释描述**非显然契约**——把"实现叙述、测试走读、review 历史、复述理由"标记删除或只放一处。
3. **核心类型文档同步**。架构骨架或能力缝隙词汇改动要更新相应的子系统页与 `type-equiv` 入口。**内部**类型不需要目录入口。
4. **注册项要清理**。每个新增注册项要过所属模块规则的处置测试。
5. **不变量 / 检查伴随要有真实语义**。一个装上去但**不会在目标回归下失败**的检查比没有更糟——它是装饰、不是证据。否定只校验服务 / 方法存在、插件元数据、静态示例、或"调用同一操作验证自身"的检查；要求伴随有**独立于被测对象**的可分歧观察（不同事件生产者、持久历史、可独立变更的数据）。当找不到这样的关系，要求省略伴随与它的发布 wiring，并在模块 README 记录一句省略理由；不要发空 installer。
6. **强证据存在**。作者跑了 [`AGENTS.md`](../../AGENTS.md) 里规定的"diff 相关本地检查"；CI 覆盖了穷尽矩阵；审查**两者都不能发现**的语义缺口。
7. **面向用户的副本走本地化**。拒绝把产品文本嵌进模板、helper 返回、可访问性属性或 primitive 默认值。要类型化字典键、统一的本地化出口、`<your UI i18n gate>` 之类的门，以及每个受影响 locale 的行为证据；保留用户 / 模型 / 网络数据与代码 token 原文。

## 手动检查项

- **意图与接口契约**：追到改动接口的**两侧**。确认实现匹配 PR 与 ADR，包括错误、取消、归属、处置。
- **生命周期与并发**：异步 setup、回调、进程、teardown 时套 [`skills/test-reliability/`](../test-reliability/SKILL.md)。在发布前查 race、await 中的取消、独立错误报告、回调收拢、reentry 前的归属、完整 detach 清理、定时停服务。
- **能力 / 消费者匹配**：追**当前**每一个消费者；按模块规则标记"消费者特化行为泄漏到接口"。反向也查：在通用服务上新增一个公开方法、唯一调用方是某个内部消费者——这是不必要的 API 扩张；改用一个私有 capability 闭包传给该消费者。
- **范围 / 归属 / 必要性**：把每个抽象、状态机、选项、防御性拷贝、兼容路径映射到它的当前契约、生产消费者、归属扩展点。挑战"不相关的功能、投机性通用"，再用根规则的公约对照。
- **配置与公开选择**：当前消费者证据或既有先例支撑了哪些默认、公开操作集、格式、引入的外部概念？没有证据时要求显式选择 / 推迟。
- **模型视角**：在每个受影响模式下检查**模型实际收到的** prompt、结果、诊断。flag 模型任务外的概念；稳定文本逐字核对；动态行为靠 snapshot / 端到端覆盖。
- **强制路径**：跟到执行该决策的**操作**；演练直接调用与绕过 schema / prompt / facade / wrapper / 监听器顺序的备选调用方。
- **借用与衍生状态**：明确每个保留值是借用还是归属；跟通知、缓存、prompt、UI echo、回放、查询视图到文档的成功点与权威源。
- **bound 覆盖整个结果**：定位完整发出 / 保留结果（含 wrapper 与元数据）的所有者。探微小值、精确上限、超大单块、多块的字节上限。
- **真实入口路径**：测试要跑**发货**的 Loader、bin、worker、ACP bridge、子进程等真实路径。手装组件抓不住 Loader 导出错误；function 插件必须具名导出其命名空间且没有 default export。
- **测试强度**：断言**在预期回归时失败**并校验外部状态 / 日志 / 事件 / 处置，而不是复述实现或相信 agent 报告。覆盖率是必要的，但不足以证明场景正确。
- **测试可靠性**：拥有资源、异步、平台敏感或 flaky 的测试，套 [`skills/test-reliability/`](../test-reliability/SKILL.md) 校验真实 worker / job 拓扑、资源分配、全局状态恢复、同步、超时预算、静默释放。
- **不变量生命周期与反例**：候选观察在发布前要拒绝；会话支撑的检查在延迟加载或 HMR 后重建持久历史；一个**故意 invalid** 的用例**通过真实 runner**失败。
- **`implemented/` ADR 与发货现实一致**：PR 实现了一条 `proposed/` ADR 时，**同一次 diff** 把它改写成"现在时发货状态"，再核对路径、名字、机制。
- **快照改动**：编辑器可见 / 模型可见改动要更新 snapshot 或说明"为什么 snapshot 不适用"。把"预期输出 diff"当**行为**改动看，不是格式噪声。
- **双语改动**：在两侧都比对意义与术语；绿色 pairing 哈希**不能**证明翻译质量。

## 报告发现

陈述缺陷、位置、影响、证据。把**局部**缺陷放在最紧密的 diff 区间；跨范围架构、scope、整篇综述用 PR 级评论。把 blocker 与建议分开，**省略已经被绿灯门强制的事**。回复用托管平台已有的 review 线程。

**接到 review 时**：逐条核对，按技术依据 fix 或 rebuttal；不要表演式同意。
