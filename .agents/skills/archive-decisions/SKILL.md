# 归档决策记录（ADR）

减少活动决策语料同时**不抹掉**仍能指导工作的历史。**逐条**语义判断；字数与年龄是盘查辅助，**不是**归档判据。

## 读契约

读 [`notes/README.md`](../../notes/README.md)、[`notes/archived/AGENTS.md`](../../notes/archived/AGENTS.md) 与当前活动的 lifecycle 指令再做分类。用当前代码、配置、包文档、生成目录、新 ADR 与 inlet 判定"它的理由是否还拥有 / 约束什么"。

## 添加 ADR 时检查替代

起草前，套 [`notes/README.md` 的创建标准](../../notes/README.md#何时写一个)。每个新 ADR 触发一次**活动 ADR 的定向审计**——覆盖同一决策、机制或被否决备选的老化记录。**写新 ADR 时**就分类完整 / 部分替代：同 PR 归档合格的 `implemented/` 三件套、保留并交叉链接部分替代或独立有用的理由、否决过时提案、删不再防止诱人错误的 `rejected/`。当新所有者吸收了每个独有命题时套 ADR 合并规则；**不要**把"已知匹配"推迟到后来的语料审计。

## 按未来价值分类

按 lifecycle 套以下结果：

- **`implemented/` —— 删除**：删掉完整三件套，当它**只**描述小 UI 调整或纯机械改动（纯粹的命名搬家、行为不变的实现切分、孤立的小 closed bug）。本地 bug fix、性能改动、新增能力、实质性的行为 / 归属决定——仅因"实现起来小"不删除。在 keep / archive 分类**之前**先套这条准则。
- **`implemented/` —— 保留活动**：当它的理由、备选、负面保证、持久 / 网络语义、归属边界、安全规则或重新引入条件**可能**指导未来改动时。判定的是**决策**，不只它的实现机制——一个纯机械改名的 ADR 仍可能承载命名、兼容、归属规则。**长度无关**。
- **`implemented/` —— 归档**：已发货决策已经**完整**且**不太可能**再指导未来，但历史理由仍值得保留；归档**前**先用上一条 "delete" 准则过滤，不该删才能归档。
- **`proposed/` —— 永不归档**：让一个活跃提案保持活动；不再值得追就用诚实的理由否决它，并满足被否决 lifecycle 格式。
- **`rejected/` —— 只作护栏保留**：仅当失败提案仍然是一个诱人、有意义的错误、且备选说得清为什么输时保留。
- **`rejected/` —— 删除**：当否决 idea 已过时、被替代、不再合理、不可能防止重提时，把整套三件套删了。修复或删除 inlet。

**不要**为凑配额归档或删除。逐条审、给类比组套同一原则、临界处靠判断、真正的边界决策记下来交班。

## 校准示例

下面的例子定标准；字数说明"大小不是判据"。

**删除**已实施 ADR 的例子：

- 已折叠的 sidebar control rail —— 533 字：封闭、小 UI 行为。
- 单一模块的搬迁 / import 改写 / 行为不变的内部实现整理：决定本来没有持久契约，承载它的代码已经移走，迁移 ADR 就失去"为什么"。

**归档**已实施 ADR 的例子（先经过上面的"删除"过滤）：

- 已经替换为生成器的文档型 ADR——历史理由留作归档。
- 一段窄适配器完整退役——行为被别处覆盖、注释里仍能看见，但不再"指导未来"。

**保留**已实施 ADR 的例子：

- 持久模型基础权威 —— 任意长度：基础权威与持久边界。
- 跨产品归属规则 —— 几百字：单一归属规则。
- 测试调度策略 —— 边界，但仍指导门调度与资源调优。
- 主动放弃的特性 ADR —— 留到对应支持落地——它陈述重新引入条件。

被否决 ADR 的例子：

- **保留**：涉及长期诱惑的架构合并提案——诱惑仍现实。
- **删除**：原本被否决的协议层要求由后来的决定解决——保留它的价值骤降。

## 归档一个已实施三件套

1. 把完整 `foo.md`、`foo.zh.md`、`foo.i18n.yaml` 三件套从 `implemented/<kind>/` 移到 `archived/<kind>/`；归档路径**刻意**不含 `implemented`。
2. **不改** body。只在两份语言文件的 `Status: implemented` 行下面插入 `Archived: YYYY-MM-DD`，归档日期相同。
3. **机械地**重新记录 sidecar 哈希只为这两条 metadata-only 编辑。不要翻译、重格式化、更新事实、修复 ADR 内部的链接。
4. 搜从活动散文入站的链接。重定向到当前权威；仅当故意引用历史时才把它指向归档路径；否则删除。**永远不要**校验或修复从归档 ADR 出站的链接。
5. 跑 `<your archive verifier>` 的 `--write` 模式。它的 append-only 先证明每个旧密封仍匹配，**再**加新三件套哈希。再跑常规验证器。

三件套一旦密封，**永不**编辑、移动、翻译、重格式化或删除。归档 ADR 仍是有效的入站链接目标，但**是历史快照，不是当前行为权威**。

## 验证 + 报告

跑归档验证器的聚焦测试、`<your archive verifier>`、`<your doc sync gate>`、`<your lint>`、`git diff --check`；其余证据走 [`skills/quality-gate-pre-push/`](../quality-gate-pre-push/SKILL.md)。

报告：保留活动的已实施 ADR、归档的已实施 ADR、保留 / 删除的 `rejected/`、否决的 `proposed/`（若有）、每个真正边界案例的字数与决定。**不要**声称"归档出站链接有效"——归档验证器**永远**不查它。
