# 修剪思维链泄漏（CoT leakage）

**思维链泄漏**是那种站在"作者会话"而非"仓库本身"视角的散文——它引用只有那次会话看得到的工件、把变更叙述成"这次改了"、跟已经离开的 reviewer 辩论。修复**不是只删**——一段话带了事实分句时，要把事实 restate 到 HEAD 的视角，再删掉它周围的转录。一段话一个事实都不带的（审计码、控制流叙述）就直删。**前置必读**：[`skills/prose-standard/`](../prose-standard/SKILL.md) 拥有本 skill 套用的"完整命题"规则。本 skill 是**指导**，不是脚本。

## 唯一的测试

对每段可疑段落问**一个问题**："一个站在 HEAD、没有会话转录 / PR 评论 / 未提交草稿访问权的读者，能不能解析每个引用、核实每个论断？"**不能**的话，把存活的事实 restate 到仓库视角，删掉其余。**能**的话，**不是**泄漏——但可解析性只过本 skill 的栏：在当前态面（README / 文档 / JSDoc），一个"可解析的变更故事"仍然是变更叙述，第 3 类会把它送到被授权的家。

## 分类

1. **死的设计会话引用**——`(decision 7)`、`(audit C2)`、`design §4.7`、`plan §1.4`、阶段标签（`T4`、`W3`、`P-I`）、"设计 ledger"、`(B ruling)`。该决策有归属所有者时按**名字 + 路径**引用它；否则删引用，把事实分句 restate 到独立成立。
2. **堆栈 / PR 视角**——"本堆栈后续的 PR"、"本 PR 新增"、"上次 commit"。陈述已发货的机制或扩展点；推迟的工作挪进 `TODO` 标记或 issue 引用。
3. **变更叙述 + 版本戳**——"曾经"、"不再"、"老的 X"、索引戳（"v1"、"这一版"、"今天"、"现在"对照过去）。陈述当前行为；一个固定的回归变成现在时反事实（"没有 X 时 Y 会发生"），**不是**仓库历史（"曾经 Y"）。
4. **Review 编排**——"review 中被拒："、"reviewer 已确认"、草稿序数（"本 note 的 v5"）、轮次归属。保留存活决策与理由为**普通事实**；删掉"是谁说的"。
5. **面向 reviewer 的辩护**——"这个 cast 是安全的——它只是…"、"这是对的因为…"。面向 reviewer 而不是维护者的注释。陈述让代码安全的不变量；代码已经自证就**删**注释。
6. **复述 / 推导转录**——控制流叙述（"先 X、再 Y"）、测试走读、显然分支的证明。删；只留非显然契约或不变量。
7. **对冲 / 规划残留**——"现在大概够"、"应该够"、无标记的推迟。升成 `TODO`/`FIXME` 或 restate 为真实的 bound；删对冲。
8. **作者语言滑落**——主流为英文时未翻译的工作语言片段（端、设计稿、`---- 私有 ----` 分隔符），或在中文副本里反过来。翻译或删除。

## 什么**不**算泄漏

不带记忆的引用检查会**两个方向都错**——既删出有意义的引用又留死引用。这些 keep 规则**字面**生效：

- **Issue 引用**——`#1470`、`TODO(name):`、"issue #N 拥有该 follow-up"在 HEAD 可解析；任何面（包括 README）都保留。**不要**搬到 ADR 里。
- **ADR 与 postmortem 内部的"已合并 PR / issue"引用**——文档策略授权的证据；按 [`docs/AGENTS.md`](../../docs/AGENTS.md) 的"变更故事路由"处理。
- **抑制注解**——`oxlint-disable … -- reason`、coverage-ignore 原因、空 catch 的解释——这些是必需的散文。改错的原因，**不要**删。
- **反事实 - 现在时回归钉**——"没有 X，Y 发生"、"朴素的 X 会…"。
- **测得 bound**——"(measured: 512 nests ≈ 0.15s)" 给常量校准；证据词 "measured" 是承重的。
- **运行时 old / new 状态**——"老连接在新连接接受前 drain" 是运行时生命周期，不是变更历史。
- **ADR 内 change-story 段里的历史阶段名**——"第一版做了 X" 在那里是当前态安全的；索引戳（"这一版"）到处都禁。
- **设计外部引用**——RFC 9110 §10.1.5 等标准；§ 禁令只覆盖未提交的内部草稿，**不**覆盖外部标准或归一化的 §-编号的已提交文档。
- **项目口吻与体裁形式**——"我们"作为项目口吻；ADR 的 Alternatives considered 段。

## 工作流

1. **scope 与排除**按 [`skills/prose-standard/`](../prose-standard/SKILL.md)：要求显式 scope；永远不碰 `vendor/` 或归档 ADR。已记录的 fixture 与 snapshot 是派生物**不是**散文目标——只有授权的行为改动需要新证据时才改归属源 / 场景并重新生成。
2. **先只读审计**：跑一组 grep 探针。每条探针**先用已知正向与近误负向各一例校准**再信任它的结果，然后语义判断每个命中。探针是工具不是定义——每轮原始清仓都发现了探针漏掉的案例，所以也**不带模式**通读 scope 内最密的散文（模块 JSDoc / README / ADR）。校准用例由仓库自身积累；失败即弃探针。
3. **owner-first fix** 按面：生成目录 → 追每个消费者，fix 源 JSDoc 或生成器模板，再重新生成所有派生品；type-equiv 围栏 → fix 源 JSDoc，再把两份字节贴回给双语页（`<your type-equiv gate>` 钉）；双语散文 → 最小更新副本并按你的轻量例程重新记录；双语围栏 → 字节级把更正过的 verbatim 块复制到两侧，再重记录；模型 / 用户可见字符串 → 走 [`skills/prose-standard/`](../prose-standard/SKILL.md)，只在有归属行为证据时改，否则保留原文并报告"已推迟"。
4. **删之前**：枚举段落命题（prose-standard）+ 检查 overcorrection traps：trim 把义务变成背书、把假设升级成已发货特性、删了真事实、丢了证据源。
5. **验证**：重跑探针，期望只剩被授权的 keep、本 skill 自己的目录与归属 ADR 的引用证据；确认每个剩余引用在 HEAD 可解析；跑受影响面的门（文档门、`<your type-equiv gate>`、`<your translation pairing gate>`）。
