# 散文写作标准

写够保留契约——然后删掉推导转录、重复、装饰。**契约**是被调用方 / 实现方 / 生产方 / 消费方依赖的义务、不变量、前置 / 后置条件、兼容性承诺。本 skill 拥有"覆盖 + 编辑判断"；用 [`docs/AGENTS.md`](../../docs/AGENTS.md) 决定"放在哪、字数、双语、文档门"，用 [`trim-cot-leakage`](../trim-cot-leakage/SKILL.md) 找泄漏的推导转录。这是**指导**，不是脚本。

`contract`、`boundary`、`shape`、`surface`、`seam`、`gate`、`vocabulary` 这些词是**先用再删**——先用之前先问"该处的精确规则 / API / 字段 / 类型 / 校验 / 时序 / 组件拆分 / 失败状态"叫什么。把 `response shape` 改成 `response fields`，把 `validation boundary` 改成 `JSON validation`，把 `module shape` 改成 `ESM exports`。仅当这些词命名了一个被广泛承认的契约 / 边界（包括 caller/callee 契约、安全 / 流程边界）时才保留。

注释描述**非显然**契约或代码不能表达的**理由**；不复述代码已经在暗示的东西。

## 输入与排除

要求显式 `scope`。缺失时报告"需要这个输入"并停下——**不要**猜"全仓"，也不要开始一场访谈。

接受 `mode: automatic | interactive`；默认 `automatic`。仅当用户**显式**要求问题或校准时才进入 interactive。

`mode` 控制问不问，不控制写不写。review / audit 报告发现不修改；显式要求的 write / fix / trim 才执行真正修改。

`vendor/`（或任何已锁定的第三方代码目录）**始终**从发现、审查、编辑里排除——即使请求范围是"全仓"。**不要**顺着符号链接溜进去。把排除放在包含 glob 之后——后面的 include 无法把它救回来：例如 `rg` 命令末尾加 `--glob '!vendor/**'`，`git` 命令加 `:(exclude)vendor/**`。请求范围**只是** `vendor/` 时，报告"没有符合的文件"。

归档的 ADR 也排除在散文审查与编辑之外——冻结快照。

**生成的目录、snapshot、fixture 都是派生品。** 改之前追每一个消费者：源 JSDoc 也可能喂一份生成的"模型可见目录"。先改归属源或场景，再重新生成所有派生品。当生成器从归属散文提取一句话时，让那句话在它去处独立成句。双语对**没有永久归属方**：哪一边都可能是这次更新的"被作者一侧"。按 [`docs/AGENTS.md`](../../docs/AGENTS.md) 的常规路径**最小**更新另一侧并重新记录镜像。

## 保留完整命题

编辑前先识别段落里的**每一条命题**。保留以下相关的每一条：

- 主体与动作；
- 条件、时序、顺序；
- 模态（must、may、never）；
- 负面保证与例外；
- 归属、副作用、失败模式、后果。

只有当**每一条事实分句**都保留且结果更清晰时，才删形容词、重复、叙述。**字少本身**不是改进。

在使用点保留**完整的本地契约**：行为、失败、归属、后果——调用方 / 维护者在那里需要知道的东西。架构、理由、算法、历史、长例子**激进地**链接到归属文档。一份解释只有**一个**家；核心契约事实可以在本地重复。

留非显然的理由——一旦背后有"可能误用或错简化的风险"。否则只陈述后果并链接理由的家。

## 各位置的必填覆盖

这不是单向缩短 pass。在代码、类型、结构不能表达**契约**时**加或还原**散文。代码已经把事实讲清楚时**不要**加注释。

- **公开 JSDoc**：文档化调用方可见的返回值区分、抛出 / 拒绝、副作用、归属、时序、取消、持久化。
- **内部注释**：为非局部结构与显然复杂的局部结构定向——不变量、race ordering、归属、安全边界、惊人失败行为。删掉控制流叙述与代码复述。
- **模块注释**：陈述模块的角色、依赖、职责、非显然架构选择；架构选择**链到**它的归属解释。
- **测试**：只解释**非显然**测试设计——为什么需要这个 fixture、断言、平台适配、真实入口、间接观察。删走读与清单。
- **Cookbook**：包括前置条件、必需动作、真实入口路径、可观察验证、简洁的告警。
- **README**：包括消费者契约——配置、语义、失败、限制、扩展点、模型可见效果。引用本模块拥有的稳定模型可见文本；链生成的目录与跨模块归属。保留持久差距与维护者陷阱，不是日常清理清单。
- **ADR**：保留独有理由、机制、备选、后果、已发货的验证证据、命名的覆盖差距。`implemented/` ADR 用现在时描述已落地现实；删计划 checklist，**不**删钉死决策的证据。
- **Postmortem**：保留事件序列、证据、因果链、影响、预防。删重复劝说或不能建立因果的实现细节。
- **Skill 与 agent 指令**：陈述行为护栏与显式范围限制（如"是指导，不是脚本 / 清单"）。保持工作流简洁并链权威来源。
- **示例与配置注释**：解释访问限制、非显然布线或加载顺序、安全姿态、回放行为、例外、易误用。**不要**叙述配置已经写出的条目。
- **Prompt 与可见字符串**：把措辞当行为。产品 UI 副本走类型化 locale 字典、以显式本地化 prop 注入；一起检查文本、可访问性名、tooltip、placeholder、格式模板，再跑 `<your UI i18n gate>`。为模型可见文本更新归属的运行型 snapshot。授权范围没有归属场景时保持原文并报告"已推迟"——不要悄悄折进纯散文编辑。
- **诊断消息**：命名失败主体或路径、被违反的规则、修正方向（仅当非显然时）。删掉内部执行叙述；把"为什么这样改"留给 ADR / postmortem。

保留可搜的机制名与有意义的模态 / 时间 / 负面强调。只规整装饰性强调。

## 工作流

1. 确认 scope、mode、当前分支或 PR base、相关 `AGENTS.md`。**不要**检查无关分支。
2. 读 [`docs/AGENTS.md`](../../docs/AGENTS.md) 与归属代码 / 文档再做判断。校准或不熟时读 distil 参考。
3. 检查**请求的** scope，不只是最大的文件。先用搜索 / 字数找候选，再语义判断。
4. 把每个候选分类：keep / add / trim / restore / restructure / defer。仅在任务授权编辑时才真改；**不要**为完成减字目标造改动。
5. 先改归属再改派生品。学到新规则后再次扫描类比段落。
6. 跑窄相关检查、文档门、`git diff --check`、可见字符串的行为测试。验证最终 diff 不含 `vendor/` 路径；遇到 vendor 匹配就报告，不要假装"已经排除"。
7. 报告检查过的 scope、已做的清晰改动、主动 keep 的内容、推迟的项、**实际跑过的**检查。

## 边界判断

只有当**至少两种**版本都满足"完整命题"但在不同原则间取舍、且本 skill 还没给出结论时，才算边界。一种命题保留的改写不算边界。

`automatic` 模式下授权编辑时直接做，对真正的边界**报告**但**不问**。**不要**为推进而弱化命题。

`interactive` 模式下把类比段落归到同一个原则下，给出两三种可行版本、推荐一个、陈述事实 / 结构差异。**不要**给明显劣的备选来凑数。

用户决定后，把原则 + 例提炼进 examples（不带 PR 历史 / reviewer 叙述），并把学到的规则套到 scope 内的每个类比段落。
