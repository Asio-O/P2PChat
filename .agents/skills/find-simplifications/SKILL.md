# 寻找简化机会

把宽泛的"找简化"请求变成**有证据**的 ADR，去删除/折叠**真实**存在的表面。本 skill 是**指导**，不是清单：跟代码走、保持判断、把少量经过证明的候选压过"凑数清单"。

## 从仓库上下文开始

- 读根 [`AGENTS.md`](../../AGENTS.md)：standing orders 与公约（包括"测试不是真理 / ADR 不是真理"）。
- 改 `modules/` 之前先扫仓库架构概览；与架构缝隙或事件词汇打架的简化要额外证据。
- 用 ADR 树与 [`notes/README.md`](../../notes/README.md) 理解**有意为之的架构**。
- ADR 之外的"双轨 LLM adapter / 双 adapter"等通常是**有意的**——它们是登记过的设计选择，不要以"低工作量"为由提案删除；除非用户明确推翻该约束。

## 强候选长什么样

一个强简化删除 / 折叠 / 降级**实际**存在的某物，且有清晰证据说明**当前设计代价超过收益**：

- 一个公开方法 / 事件 / 配置旋钮 / 注册通知 / helper / 包 / 持久事件 / 测试产物——**没有**生产消费者。
- 测试或文档是唯一消费者，且它们钉死的行为**不**承载。
- 两个表示镜像同一事实（特别是跨持久会话事件与瞬态 `agent/*` 事件）。
- 一个缝隙有"每个实现都必须支持"的方法但**没有**消费者使用。
- 一个独立的包**只**为了测试 / demo / 支持代码而存在，并增加发布 / 依赖开销。
- 一个特性实现投机性通用性——多会话 / 会话加载、后台任务编排、运行期注册失效、中途转向、工具拥有的 UI 渲染等没有产品所有者的设计。
- 一个不变量 / 回滚路径 / 期望输出集 / 特殊测试**只**为了保护一个未使用的 API。
- 手卷代码重写一个维护良好的外部包或当前引擎内置能做的功能；改用可以**删除实现 + 它专属的测试**。
- 简化后行为可能略变，但新行为**仍合理**且更容易解释。

**薄候选**不够一个 ADR：删一个 typo、跑一次 knip、删一个有意为之的后端 / adapter、没调用点证据就说"这看起来复杂"。

### 审计不变量伴随

只有当不变量伴随**对比独立产生的、能分歧的观察**时它才有用。删除空 installer 与"只检查服务存在、插件元数据、固定示例、调用同一变更的检查"。每次省略都把 export / 构建入口 / 不变量专用编译器引用 / 依赖 / 伴随专用测试删掉，并在两份 README 里记一句"包级原因"。**保留**伴随专属：它对比**不同的**事件生产者、持久历史、可独立变更的数据，即便该模块也同步校验输入。

## 广搜

用户要"广度"或"多个候选"时用并行 subagent。给每个 agent 一个领域，要求证据。常用领域：

- 主循环与会话日志：turn / step 边界、转向、中止 / 取消、持久事件、回放、加载 / 恢复。
- ACP 自动化与人类 UI API：prompt 结算与 teardown（协议侧）；转录渲染与交互态（UI 侧）。
- LLM / 工具 / 系统 prompt：stream / generate API、assembler、注册表、工具 schema 默认、呈现 hook。
- Bash 与工具执行：前台 / 后台拆分、job 归属、输出溢出文件、执行器方法。
- 包 / 例子 / 脚本 / 测试：包拆分、静态清单、冗余 snapshot 期望输出、支持包。

subagent 不可用就自己模拟同样的广度。**不要**让"第一个够好的候选"停下 survey。

**先看最大的生产代码 delta。** 一个泛简化审计在"明显未用符号"之后就停，会漏掉"重复生命周期 / 防御机制 / 双份状态机"承担最多成本的文件。

## 散文与代码同步简化

把注释与文档当"被维护的表面"。survey 涉及散文时套 [`skills/prose-standard/`](../prose-standard/SKILL.md)。

- 删"复述代码"或"解释行为属于别处"的注释；保留必需的本地契约。
- 文档留在它归属的层；除非改"被维护的契约"，否则删实现细节与稀有情况。

## 审计信任与生命周期边界

对每个防御性拷贝、freeze、校验、回调捕获，标出值从哪来、接下来归谁。同进程类型化服务 / 插件调用通常**借 readonly**；解析器、配置加载器、队列、模型 / 工具 JSON、持久文件、worker、进程、跨网络 decoder 拥有或校验它们的数据。围绕"敌对 getter / 伪造类型对象 / 回调替换 / 同进程交接后变更" 的测试是"投机性契约"的迹象，不是"自动验证"必须保留的理由。

复杂异步代码画所有权关系图，把 sentinel / readiness promise / 取消路径 / disposer / state flag 各映射到一个独立的所有者或迁移。多个机制镜像同一 liveness 或 settlement 事实时，提案"一个事务 / 生命周期 controller"。**保留**同步发布 / 回滚、回调收拢、首发终局仲裁、worker / 进程归属、定时停服务的独立机制。

## 手卷 vs 依赖

引入依赖是合法的简化动作，不是策略例外——依赖策略拥有的是 bar。survey 时对协议解析器 / 帧化器 / retry / backoff 循环 / glob matcher / diff engine / 类似基础设施问：**当前引擎 floor 下的现成依赖或内置**是否已经做了？

把"依赖替换"候选**当普通候选**证明，再加：

- 读手卷实现、命名包覆盖的精确面；包没覆盖的残留语义从这次替换里减掉并留在 ADR。
- 诚实地查包（维护、采用、传递脚印）；引擎 floor 有内置时优先选内置。
- **先**查 ADR 树：vendor / 一些已经登记过的设计（schema、twin adapter 等）已 settled——一个替换要打掉它就得打掉登记过的理由，**不**只引用策略。
- 称净删除：实现 + 专属测试 + 文档，减去剩下的胶水。一个只把同一复杂度挪了位置的包装不算赢。

## 证明或拒绝每个候选

为每个符号或行为**先分类消费者再写**：

- **生产语料**：`<module>/src`、`<examples>/src`、`<examples>/**/*.yml`、runtime 脚本、loader / config 路径。
- **非生产语料**：测试、README / 文档、ADR、snapshot、生成期望输出、注释。
- **模糊语料**：例子与脚本（可能是产品 smoke 路径）。分类前**先**看用法。

先 `rg`。好的搜索包括精确符号、事件名、包名、配置 key、方法名（同时 `.name(` 与 `name(`）、任何网络字符串。然后读调用点、公开接口、动态事件名、测试、文档、loader 路径。

下列情况**拒绝 / 降级**候选：

- 存在生产调用方，简化是特性决定而不是清理。
- 该 API 由 `implemented/` ADR 或来之不易的防御模式**显式**论证，新证据打不掉那个理由。
- 删了它会强制拆无关 churn 而不真的减公开 API 或必需行为。
- 想法正确但微小。加一个聚焦的 `TODO/FIXME/XXX`，按仓库约定使用紧迫性语义。

## 合并被替代的 ADR

用户要"缩减或合并 ADR 树"或"被实现的简化让某 ADR 过时"时，审计 ADR 树。**不要**把"每个代码简化 survey"扩张成"全仓 ADR 审计"。

用 [`skills/archive-decisions/`](../archive-decisions/SKILL.md) 做保留判断与归档机制。低未来价值的 `implemented/` 三件套挪到 `archived/{class}`；`proposed/` 永不归档；不再防止诱人错误的 `rejected/` 删除。简化当前散文 / 代码时**不要**编辑归档 ADR。

按 [`notes/README.md`](../../notes/README.md#何时写一个) 的删除规则——**不要**在这里复述 / 弱化它。对每条候选链：

1. 从发货代码、配置、生成目录、包文档、新 ADR 与 inlet 已确认当前所有者；日期与标题是盘查线索，**不**是证据。
2. 把旧 ADR 分为"完全 / 部分替代"。任何存活的行为、当前契约、持久格式、兼容义务、独立仍然成立的否决备选都让它变成"部分"。**能转到当前所有者的理由本身**不构成部分替代。
3. 完全替代：把**每个**独有的理由、备选、后果、已发货验证证据、命名覆盖差距**全**搬到当前所有者。**只**描述被删实现机制的清单**不是**这类决策事实。
4. 修复每个入站链接，然后**同一次**删英文 ADR、中文副本与一致性记录。
5. 编辑后**精确**搜文件名、符号、配置 key、事件名、网络字符串。保留部分替代交叉链接与更新状态。

**增了又删**特性是常见完全替代。让删除 ADR **只**在以下条件**全成立**时拥有历史：特性**不在**生产代码、配置、schema、持久 / 网络格式、迁移与兼容行为；**无**当前文档把它呈现为可用；**无**测试把它当受支持行为跑。删除理由与验证"确实不在"的测试可以保留。删除方必须保留：特性原本为什么存在、现在为什么不再合理、不完全删除的备选、放弃的能力、重新引入的条件、完整不在性的证据。仅验证被删行为的旧测试与实现机制**不是**当前验证证据。

只删一个传输 / 默认 / 实现 / 呈现是部分替代；持久数据或兼容处理存活也是；删除 ADR 还未带够理由防止意外重引入也是。一个当前负向设计决定**可能**正当需要自己的 ADR，即便被删实现已经不在。

## 写 ADR

在 `.agents/notes/<lifecycle>/<class>/yyyy-mm-dd-topic.md` 下建一份文件，遵循 [`notes/README.md`](../../notes/README.md) 的 lifecycle 与分类规则。散文段落一行物理一行，用相对 Markdown 链接。

推荐如下结构，idea 需要时调整：

- `# Agent Note: <action-oriented title>`
- `Status: proposed`
- `## Problem`：命名当前 API、引用相关文件、陈述消费者证据。把生产调用方与测试 / 文档分开。
- `## Proposal`：准确说"删 / 折叠 / 降级 / 重新归属"什么。包括测试、文档、README、JSDoc、事件词汇、snapshot、生成文件清理（相关时）。
- `## Why not keep it?` 或 `## What we give up`：让最强反驳清楚。
- `## Acceptance criteria`：可观察终态 + 门。
- `## Risks`：公开 API 改动、行为改动、未来产品需求、为什么 trade-off 仍合理。

具体到一份"实现的 PR 能跟这条线走"。避免"简化这个模块"这种含糊 ADR。当提案与现有 ADR 重叠时，**把有用细节合并进现有 ADR**，不重复。

## 内联 TODO

只在小、局部、显然有用但**不是**持久设计决定的地方加 `TODO/FIXME/XXX`。短而可执行：

- 用稳定 tag 命名——`TODO(double-default)`、`XXX(unused-default)`。
- 说明为什么可以重访、什么动作能简化它。
- 不要为投机抱怨或"需要 ADR 级别决定"的行为加 TODO。

## 吸纳别的 PR / branch

把同辈 branch diff 到 `origin/master`——**不**到当前 PR branch——这样能看到它的独立贡献。每个条目：

- 搬**非重叠**的 ADR 或 TODO，过质量门。
- **重叠**材料合并进**现有** ADR / 当前主题。
- 不要为了凑数搬重复或低置信度提案。
- 更新 PR 描述让 reviewer 看真实候选数与 scope。
- 关闭重复 PR 只在**用户**明确要求或**你**显然拥有 housekeeping 时做。

## 验证 + PR hygiene

仅文档的 ADR 工作至少跑 `<your build>、<your lint>、git diff --check`。代码注释或 skill 改动也跑相关校验器。**其他**证据从外发 diff 挑；pre-push hook 只贡献 typecheck。

开 / 更新 PR 时总结：

- 加了几个 ADR / 内联 note，合并了几个，保留了几个部分替代，删了几个。
- 主要 survey 的领域。
- 主动排除了什么。
- 哪些检查通过。

每个合并组：命名旧与当前所有者、陈述完全替代的证据、说明删除为什么安全。若"增了又删"扫描没找到合格 ADR，报告"无"与"代表的部分案例保留"。

survey 还在展开时用 draft PR；候选集、review 响应、validation 都 settled 才 ready。
