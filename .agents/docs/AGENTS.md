# AGENTS.md — 文档标准

> **来源**：从 `deepseek-ai/deepseek-harness` 的 `docs/AGENTS.md` 通用化而来。
> 与本文件配套使用的有 [`skills/prose-standard/`](../skills/prose-standard/SKILL.md) 和 [`skills/trim-cot-leakage/`](../skills/trim-cot-leakage/SKILL.md)——本文件管"放在哪里、用什么格式"，那两份管"句子怎么写"。

本规范定义**人类可读文档**的结构、Markdown 层级、写作规则与字数预算。决策记录（ADR）见 [`notes/README.md`](../notes/README.md)；postmortem 与本规范平行，不在此处约束。

## 一处一事实（tier taxonomy）

每个事实只有一个家**——属于它的层级。其他地方只放链接。**

| 层级 | 职责 | **不**应当出现在这里 |
|---|---|---|
| 根 `AGENTS.md` | standing orders：每个会话里都需要在场的规则，一到三行，链接到完整详情 |
| 子目录 `AGENTS.md`（`modules/`、`docs/`、`notes/`） | 该子目录补充规则 | 仓库全局规则（已在根文件） |
| `<modules>/README.md` | 该模块的对外契约：配置、语义、限制、扩展点、副作用 | 仓库全局规则的复述、其他模块的细节 |
| 架构概览文档 | 整体地图：组成、核心模块、循环、缝隙、扩展点 | 类型定义（→ 子系统页）、单模块细节（→ 模块 README）、决策理由（→ ADR） |
| 子系统参考页 | 一个子系统一页：类型定义、语义、生成的 API | 行为叙述（→ 架构概览） |
| ADR（决策记录） | "为什么"——备选、放弃的能力、需要持续验证的契约。`implemented/` 里的 ADR 用**现在时**描述已落地现实 | 迁移步骤、验收清单、spec-speak（"应当…"） |
| `postmortem/` | 事件叙事 —— 唯一允许"故事"风格的地方 | — |
| 持久化历史 / 格式参考 | 跨版本兼容契约、完整历史格式快照 | 仅行为改动 |
| 教程 / cookbook | 步骤化 how-to，带可验证步骤 | 设计理由（→ ADR） |
| 用户文档 | 面向终端用户的发布指南 | 内部贡献者流程、决策历史 |
| 贡献者文档 | 贡献者日常开发、CI 摘要 | 运行时 / 版本理由（→ ADR） |
| 生成式参考（自动生成 + 自动新鲜度检查） | 由源码生成的权威清单 | 手工编辑 |
| Skills（`skills/`） | 可复用工作流和专项判断标准 | 产品 / 运行时契约（→ 详情文件） |

## 文档结构规则

1. **只描述当前状态**。历史留在 commit、PR、ADR、postmortem 或专门的持久化记录里；其他散文命名"机制"，不命名"变更"。
2. **一类一地方**：bug 走 postmortem；理由走 ADR；步骤走 cookbook；类型定义走子系统页；模块契约走 README；standing orders 走根 `AGENTS.md`。
3. **每段一行**（`<your markdown wrap gate>` 强制）：段落一个物理行；代码块、表格、列表结构保持原样。
4. **TypeScript 代码块要能编译**（`<your doc typecheck gate>`）；贴类型时用原始 JSDoc 的特殊代码 fence（如 `` ```ts public-api ``），由 manifest 校验不会漂移。
5. **类型与文档同步**：重新整形一个公开类型时，所属子系统页要一起改；删除或新增类型不能"漏掉文档"，也不能"漏掉代码"。
6. **成对翻译同步**（如果你有双语文档）：术语表 → 单遍 agent 工作流 → 记录镜像哈希；不要"自动翻译流水线"代替人工完成。

## 字数预算管理

`<your cover type budgets gate>` 强制对比 standing 文档与字数上限。红灯时按以下顺序处理：

1. **搬迁**：内容属于其他层级就搬走，留一行链接。
2. **压缩**：内容该在该层但可以更短。
3. **提高上限**：仅当真的需要这些字数时才提高；要在 PR 里说明 manifest diff。预算本身是看门狗，不是节流阀。

预算**不是减字目标**：处于目标值时保留 ≥ 5% 余量；超过目标值时**冻结上限**，先搬 / 压再改上限。仅在文件确实还有余量时才下调上限。

## 写作检查清单（slop checklist）

以下问题在任何文档里都要被搜捕；`skills/prose-standard/` 是这一清单的扩展版：

- **重复规则**：搜一个特色短语，全仓只保留一份家，其余只放链接。
- **历史越界**：陈述当前事实，把历史交给历史的所有者。
- **实现状态注解**：散文里写"已实现！"、"将来…"等——这些会在 commit 之后就腐烂；状态由代码 / 清单 / CI 表达。
- **手工复刻的目录**：手抄 JSDoc、手抄事件清单、手抄测试清单——这些都该由代码或生成器表达。
- **推理转录**：一步步实现叙述、显然分支的证明、测试走读、被否决的局部备选——保留结论与契约，删除推导路径。
- **理由重复**：相邻方法同级解释，不在能力/工具函数级别讲一次。
- **段落墙**：一段装多条规则与旁注——拆开，或者下沉到子文档。
- **强调膨胀**：到处加粗、CAPS、"关键的是"——强调留给改变行为的那一条。
