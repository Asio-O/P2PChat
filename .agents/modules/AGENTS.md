# AGENTS.md — 模块 / 子目录补充规则

> **来源**：从 `deepseek-ai/deepseek-harness` 的 `packages/AGENTS.md` 通用化而来。
> 这些规则是仓库根 [`AGENTS.md`](../AGENTS.md) 的**补充**，不是替代。

适用于仓库内的**单一模块**（`modules/<module-name>/`、`packages/<pkg-name>/`、任何有自己 `README` 的子目录）。如果你的仓库结构不同，把模块替换成你自己命名的"自带 README 的子目录"。

## 模块边界

1. **公开导出有清晰形态**：库 / 服务 / 扩展点（plugin）/ 配置（bundle），每种形态的安装与激活方式不同——`README` 必须根据顶层触发的事实（`package.json` 字段、入口导出形态）而非路径名给出正确分类。
2. **能力缝隙三角色**：Service Definition / Service Provider / Consumer 缺一不可；只有真正独立演化时才拆。
3. **可选服务用显式 lookup**。保留属性代理给**已声明**的注入；否则用显式 `lookup` / `get` 读全局服务表。
4. **产品可见的扩展点要带真实路径的端到端测试**。手装组件的局部测试不够；要从真正的"组合根 + 应用"启动，只 mock 外部服务或非确定性输入，断言产品可见 / 持久化 / 用户可见输出。

## 异步与生命周期

5. **一个异步操作对应一个生命周期控制者**。准备、取消、释放、保留、sentinel 状态各自有**独立的所有者 / 结算点**——否则折叠；保留回滚、回调收拢、定时停服务。
6. **私有链路从主调用者派生再捕获**。在主调用者作用域下派生"会话"，让操作本地 helper 闭包它。在生命周期、会话日志、服务、权限、worker / 进程、持久化、跨网络边界**保持显式**——不要把叶子 helper 从 `Session` 拓宽到 `Context` 只为少传一个参数。
7. **发布状态只在提交点发布**。通知、衍生状态、缓存、prompt、UI echo、回放、查询视图——只在原操作成功后发布；从**一个权威来源**派生。
8. **把 bound 套在整个结果上**。字节、token、项数、时长的限制套在"完整发出 / 保留的结果"（含 wrapper 与元数据）；测微小值、精确值、超大单块与多块的字节上限。
9. **注册项要有处置证据**：通过"快速重载 (HMR) 安全测试"或等价机制，断开连接后验证注册项真的消失——否则就是 leak。

## 公共契约

10. **从消费者视角写模型面契约**。prompt、tool schema、结果、诊断只包含任务相关概念——不带 UI、传输、实现词汇。稳定的模型可见文本逐字固定；动态行为用 snapshot 或端到端覆盖。
11. **在执行它的操作里强制决策**。schema 省略、prompt 过滤、facade、wrapper、监听器顺序都不是强制——若直接调用或备选调用方能绕过，它们就没生效；要测强制通过执行器发生。
12. **每个抽象都要有当前所有者与需要**。状态机、选项、防御性拷贝、兼容性路径——都要挂到当前契约或当前消费者；行为留在拥有它的扩展点。
13. **公共选择要有证据**。一个默认值、公开操作集、格式、引入的外部概念都要由当前消费者证据或既有先例支撑；否则要求显式选择或推迟。

## 模块产物约定

14. **每个模块都带自己的 `README`**：配置、语义、限制、扩展点、副作用（产品/性能/缓存）——同一次提交里更新。
15. **`tests/` 在模块根，不在 `src/__tests__/`**——避免源码与测试混在同一编译单元。
16. **构建配置分层**：基础 tsconfig（`tsconfig.base.json`）→ 模块根 tsconfig → 子 face（host / client / server / shared）——只有真正多 face 才分裂。
17. **`src/types.ts` 只放类型**，不放运行时——保持类型边界清晰。
18. **持久的消费者差距与不可见的维护者约束** 写在 `## Known Limitations and Deferred Work`；日常清理留给 TODO 或 ADR。
